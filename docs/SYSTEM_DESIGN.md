# 系统设计与数据契约

## 目标

建立由本人控制、跨产品可用、可检索、可更新、可回溯的个人文档系统。主档案在GitHub私有仓库；任何产品都可通过自己实际支持的方式读取导出的Markdown或JSON。并非所有产品都能直接访问私有GitHub。

## 唯一事实源

`facts.json`是事实台账，`sources.json`是证据台账，`projects.json`组织项目关系。Markdown档案、上下文、时间线和复核清单都由台账派生，避免一处更新后其他文件继续传播旧状态。

一个来源可能支持多个原子记录。一条记录只表达一个可辨别事项，避免“公司已成立、产品已上线、销售增长”被合成无法局部纠错的一句话。为了保留限定条件，紧密相连的前提和结论可在同一条中。

## 事实字段

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定ID，删除后不复用 |
| `domain`、`topics` | 主主题与检索标签 |
| `statement` | 带必要限定条件的中文原子叙述 |
| `kind` | fact / preference / constraint / goal / requirement / inference / interest / unknown |
| `status` | current / historical / documented / candidate / unknown / superseded / retracted |
| `evidence` | 原话、检索原话、记忆摘要、文件要求、文件记录、账号核验、第三方线索或助手分析 |
| `sensitivity` | public / private / restricted；只决定导出筛选 |
| `public_approved` | 本人逐项明确批准公开后才为true |
| `observed_at` | 该陈述或状态当时的日期；不详为null |
| `recorded_at` | 入库日期，不可冒充原事件日期 |
| `review_after_days` | 复核窗口，null表示无自动到期窗口；不是事实有效期 |
| `sources` | S开头来源ID，不直接嵌入认证链接 |
| `priority` | 导出优先级1–5，1最高；不表示事实更真实 |
| `supersedes` | 这条新记录明确替代的旧事实ID |

## 时间与冲突

`current`表示最新可见陈述，并不等于刚刚核验。`documented`表示文档记载，不等于实测。`historical`始终按当时事实读取。`candidate`表示身份线索或推断有待确认，不能作为既定背景。

导出时根据观察日期计算 `freshness`，超过复核窗口标为 `review_due`。历史事实、计划、未确认项即使未到期，也不能升级为今天的事实。

新状态明确替换旧状态时，新增记录并关联旧ID；旧记录留存于历史。导出先在全台账计算替换关系，再按权限筛选，防止限制级新记录被过滤后旧说法复活。历史模式可显示被替换记录并保持标记。

两份来源冲突时，优先考虑用户当前明确纠正、原始证据、时间和适用版本。新日期不自动胜过更强但旧的证据；若描述不同产品区域或版本，应并存而不是强行覆盖。

## 接入层

Markdown面向人和对话附件，JSON面向程序和索引。JSON导出提供schema版本、数据版本、资料截止日、导出检查日、场景、访问范围和记录数组。保留事实ID，方便产品把后续更正对应回主档案。

首版无需数据库、向量搜索、LLM调用、MCP服务或多Agent。未来确有检索规模和产品接入需要时，可以增加只读适配器；仍以台账为事实源，并保留每次导出的版本与范围。

## 已知限制

- 只覆盖本轮可访问记录，不能替代完整聊天导出。
- 来源定位可能需要当前账号权限；未把外部PRD全文复制进仓库。
- 没有自动接入全部新聊天，也没有自动跨产品同步。
- 标签不是加密；拥有仓库读取权的人可以看到全部已提交文件。
- 导出按条数裁剪，不计算具体模型的Token数。
- 自定义Python校验是运行时校验；JSON Schema同时用于文档和编辑器提示。
- 本轮未审计OfficeFlow或其他产品源码，不证明产品发布与营业数据。
